# Crew Package v2 설계 설명서 (수정본 2)

작성: 2026-11-11 · **코드는 수정하지 않았다. 이 문서는 개발 착수 여부를 판단하기 위한 설계서이고, 승인 전에는 개발을 시작하지 않는다.**

표기
- 🟢 **확인된 사실**: 현재 코드를 읽고 확인함 (파일·함수 기준)
- 🔶 **v2 제안**: 이번 패키지 v2에서 만들자고 제안하는 것 (아직 없음)
- ⏳ **Memory 단계에서 결정**: 지금 정하지 않음

제품 개발 우선순위(변하지 않음): ① 인터뷰 기반 크루 생성 ② 크루의 실제 업무 능력 ③ 사용자별 Memory ④ 백업·내보내기·가져오기·복원 ⑤ Android↔Android 이동 검증. **패키지 만들기는 ④번 단계다.**

## 1. 현재 구조 🟢

크루는 한 곳이 아니라 여러 곳에 나뉘어 저장된다.

| 구성 | 저장 위치 | 내용 |
|---|---|---|
| 지침·자료 | 크루 폴더 `<CREWS_DIR>/<폴더명>/` | `CLAUDE.md` + 사용자가 둔 자료. 새 크루 폴더명은 `crew-xxxxxx`, 예전 크루는 이름 그대로 |
| 화면 정보 | `data/ui-state.json`의 `crew` 맵 | `name, icon, blurb, group, examples[], author` |
| 템플릿 출처 | 같은 파일의 `tpl` 맵 | 템플릿 id |
| 실행 설정 | `data/projects.json` (`projectConf`) | 크루별 `model`, `effort` |
| 권한 규칙 | `PERM_FILE`의 `perms[크루 폴더명]` | "항상 허용" 규칙 `{rule, cmd, ts}` |
| 대화 | `data/conversations/*.json` | `sessionId`, `messages`, `participants`, `crew`, `dir`, `prefs`, `handoff` |
| 채팅방 결과물 | `<ROOMS_DIR>/chat-xxxxx/` | 방에서 만든 파일 |

- 실행: `claude` CLI를 띄우며 `--model`, `--effort`, `--resume <sessionId>`를 준다. 방 폴더에서 일하는 크루는 `CLAUDE.md`(최대 20,000자)를 시스템 프롬프트에 끼워 넣는다. **즉 지침은 실제 실행에 직접 영향을 준다.**
- **Memory 기능은 코드에 없다.** 가장 가까운 것은 대화 기록, `sessionId`, 채팅 이어가기의 `handoff` 요약뿐이다.

## 2. 지금 있는 내보내기·가져오기 🟢

| 기능 | 단위 | 담는 것 | 안전 처리 |
|---|---|---|---|
| **크루 코드 v1** (`public/app.js` `crewEncode/Decode`) | 크루 1개, 글자 한 덩어리 | `name, icon, blurb, author, examples, instructions` (v1만 허용, 지침 50,000자·코드 100,000자 상한) | 숨은 글자 제거, 의심 단어(비밀번호·token·curl 등) **경고(막지는 않음)**, **미리보기 후 추가** |
| **채팅 zip** (`/api/rooms/export·import`, `tools/gamja-zip.js`) | **채팅방 1개**, 최대 1GB | `gamja-room.json`, `conversation.json`, `crew/CLAUDE.md`, `folder/…` | 아래 3절 |

## 3. 현재 코드에서 확인한 보안·안정성 사실 🟢 (이번 검토에서 새로 확인)

1. **파일 필터는 이름만 본다.** 내보낼 때 `GH_SECRET`(id_rsa, token, password, `*.pem`, `*_deploy` 등), `.env`, `.git`, `node_modules`, 심볼릭 링크를 이름으로 제외할 뿐, **파일 내용은 검사하지 않는다.** `config.json` 속 API 키나 평범한 이름의 개인정보 파일은 그대로 들어간다. `CLAUDE.md`도 내용 검사 없이 담긴다.
2. **채팅 zip 가져오기에는 미리보기·경고·승인이 없다.** 크루가 없으면 zip 안의 `crew/CLAUDE.md`를 **바로 새 크루의 지침으로 설치**한다(크루 코드 가져오기와 달리 의심 단어 경고도 없다). 이 지침은 이후 시스템 프롬프트로 쓰인다. → 지금도 존재하는 구멍이다.
3. **가져온 크루 이름이 폴더명이 된다.** 가져오기는 `manifest.crew`를 그대로 크루 폴더명으로 쓴다(`isProjectName` 검사만). 이미 있는 이름이면 지침은 덮어쓰지 않고 방만 붙인다.
4. **권한 규칙은 크루 폴더명에 묶여 있고, 크루를 지우거나 이름을 바꿔도 정리되지 않는다.** 삭제는 `projectConf`만 보관·삭제하고 `perms`는 그대로 두며, 이름 변경은 `perms`를 옮기지 않는다. → 3번과 합치면, **같은 이름의 크루를 가져올 때 예전 "항상 허용" 규칙을 이어받을 수 있다.** (패키지가 권한을 가져오지 않는 것과 별개로, 새 아이디 발급이 필요한 이유다.)
5. **zip 크기·경로는 방어한다.** 가져올 때 `..`·절대 경로·역슬래시 거부, 암호 zip·알 수 없는 압축 방식 거부, 선언 크기와 실제 풀린 크기 모두 한도(1GB) 적용, 항목 수 상한 20,000.
6. **무결성은 구조 검사까지만.** zip에는 CRC32가 기록되지만 읽을 때 검증하지 않는다. 해시 목록도 없다.
7. **가져오기 실패 정리가 불완전하다.** 중간 실패 시 새 방 폴더는 지우지만, 그 전에 만든 **새 크루 폴더(지침 포함)는 남을 수 있다.**
8. 크루 코드 v1은 브라우저에서만 처리되고 서버를 거치지 않는다.

> **범위 분리**: 위 2·4·7번(채팅 zip 가져오기의 미리보기 부재, 권한 규칙의 이름 묶임, 실패 시 정리)과 그 해결책은 **별도 문서 [import-permission-safety-proposal.md](import-permission-safety-proposal.md)** 에서 다룬다. 그 작업은 패키지 v2와 상관없이 먼저 한다. 이 문서의 8절(가져오기 절차)은 그 결과(검사 → 미리보기 → 승인 → 임시 폴더 설치)를 크루 패키지에도 재사용한다는 뜻이며, 패키지 개발은 여전히 ④단계다. 3절에 적은 "권한 규칙은 정리되지 않는다"는 사실은 그 문서 1절에서 더 자세히 확인했다(현재는 새 "항상 허용"을 만들 수 없고 예전 규칙의 잔재만 남아 있음).

## 4. 데이터 영역 분리 (4영역)

| 영역 | 해당 데이터 | 이번 v2 패키지 |
|---|---|---|
| **Crew Identity** | 🟢 이름·아이콘·소개·분야·예시·작성자, `CLAUDE.md`, 템플릿 id, (선택) 자료 파일 | 🔶 포함 |
| **Runtime Preferences** | 🟢 `model`, `effort` | 🔶 **Identity와 분리된 별도 파일**(`runtime.json`). 가져올 때 자동 적용하지 않고 "기본값으로 쓸까요?"를 묻는다 |
| **Personal Memory** | 🟢 아직 없음 | 🔶 **v2에 넣지 않는다.** `memory/` 자리도 예약하지 않는다. ⏳ 저장 단위(크루별/방별), 형식, 승인된 것만 지침으로 올리는 방식은 Memory 구현 때 결정 |
| **Credentials & Permissions** | 🟢 `github.json`, `.env`, 로그인, `perms`, `ALLOWED_TOOLS`, `sessionId` | 🔶 **절대 넣지 않는다.** 가져온 크루는 권한 0에서 시작한다 |

## 5. Share와 Backup (🔶 제안)

| 데이터 | Share (남에게) | Backup (내 다른 폰으로) |
|---|---|---|
| 이름·아이콘·소개·분야·예시·작성자 | 포함 | 포함 |
| `CLAUDE.md` | 포함 | 포함 |
| 자료 파일 | **기본 제외** | **사용자가 선택** (아래 목록 미리보기) |
| `runtime.json` (모델·강도) | 포함하되 받는 쪽이 선택 | 포함, 복원 때 선택 |
| Personal Memory | 없음 | ⏳ 나중 |
| 대화 기록 | 없음 | **기존 채팅 zip이 담당(그대로 유지)** |
| 인증정보·권한·`sessionId` | 없음 | 없음 |

공유 코드(`gamja-crew:`)는 Share의 가벼운 형태로 계속 쓴다.

## 6. 패키지 형식 (🔶 제안) — JSON + zip, 새 라이브러리 없음

```
<이름>.gamja-crew.zip
├─ gamja-crew.json  # format:"gamja-crew", version:2, kind:"share"|"backup", exportedAt, 앱 버전,
│                   # files:[{path, size, sha256}]   ← 무결성 목록
├─ identity.json    # name, icon, blurb, group, examples[], author, template
├─ runtime.json     # model, effort            (선택)
├─ CLAUDE.md
└─ files/…          # 선택한 자료만 (Backup, 또는 사용자가 직접 켠 Share)
```
- 해시는 Node 기본 `crypto`(sha256)로 만든다. **SHA-256은 "파일이 중간에 바뀌거나 깨지지 않았다"는 무결성 확인일 뿐, 만든 사람이 누구인지(제작자 인증)나 내용이 안전한지(신뢰성)를 보증하지 않는다.** 악의적인 패키지도 해시는 정상이다. 그래서 해시가 맞아도 8절의 미리보기·경고·승인 절차는 생략하지 않는다. 서명·암호화는 이번 범위에 넣지 않는다.
- 새 기록은 허용 목록 방식(정해진 필드만 읽고 나머지는 무시)으로 읽는다.
- 옛 크루 코드 v1과 옛 채팅 zip은 계속 읽는다.

## 7. 내보내기 안전 (🔶 제안)

1. **이름 필터는 보조 수단이다.** 기존 필터는 그대로 두되 안전의 근거로 삼지 않는다.
2. **내보내기 전 포함 목록 화면**: 담길 파일 이름·크기를 모두 보여 주고 파일별로 뺄 수 있게 한다. 사용자가 확인해야 내보내기가 켜진다(지금 크루 코드의 "개인 정보 없음 확인" 체크 방식을 재사용).
3. **내용 경고 검사**: `CLAUDE.md`와 텍스트 자료에서 키 같은 패턴(`sk-…`, `AKIA…`, `-----BEGIN`, `password=`, 토큰 모양 긴 문자열)을 찾아 해당 파일에 ⚠를 붙인다. 지금 크루 코드의 `WATCH_TERMS` 경고와 같은 성격이다. **완벽하지 않다는 문구를 반드시 보여 준다**(경고이지 보증이 아님).
4. Share는 자료 파일이 기본 꺼짐이다.

## 8. 외부 크루 가져오기 절차 (🔶 제안)

1. **검증**: 형식·버전, 필드 길이, 숨은 글자 제거, 경로 검사, 크기(압축·해제 후), 해시 대조. 하나라도 실패하면 **아무것도 설치하지 않는다.**
2. **미리보기**: 이름·작성자·지침 **전문**·예시·포함 파일 목록을 보여 주고, 의심 단어와 숨은 글자 제거 수를 알린다(지금 크루 코드 가져오기 화면 재사용).
3. **외부 크루 안내**: "이 지침을 Claude Code가 읽고 실제로 파일을 만들거나 고칠 수 있어요. 아는 사람이 보낸 것인지 확인하세요."
4. **사용자 승인 후 설치**: 항상 **새 크루로**, **새 아이디(`crew-xxxxxx`)를 발급**한다. 같은 이름이 있으면 이름 뒤에 번호를 붙인다. 기존 크루는 덮어쓰지 않는다.
5. **권한 0에서 시작**: `perms` 등록 없음. 실행 때는 지금의 위험 수준별 승인 정책이 그대로 적용된다. **가져오는 것과 신뢰하는 것은 별개다.**
6. **실패 시 원상복구**: 임시 폴더에 먼저 풀어 검증한 뒤 한 번에 옮기고, 도중에 실패하면 임시 폴더와 만들던 크루 폴더·화면 정보를 모두 지운다.
7. 같은 절차를 **기존 채팅 zip 가져오기에도 적용**해야 한다(3절 2번). 이것은 패키지 v2와 별개로 앞당겨 고칠 가치가 있다.
8. 모르는 새 버전은 "감자를 업데이트하세요". 가져올 수 없는 항목(예: 이 기기에 없는 모델)은 설치 후 "다시 정할 것"으로 표시한다.

## 9. 데이터 통합 방식 (🔶 제안, 이전 안 수정)

이전 판의 "크루 정보를 서버 한곳에 모으기"는 **하지 않는다.** 대신 **Export Adapter**를 만든다: 서버에 `collectCrew(폴더명)` 하나를 두고, `ui-state.json`·`projects.json`·크루 폴더에서 필요한 필드만 읽어 패키지용 객체로 조립한다. 가져오기는 반대로 `installCrew(객체)` 한 곳이 각 저장소에 쓴다. 기존 저장 구조와 동작 중인 기능은 건드리지 않는다. 단일 관리 지점은 장기 과제로 남긴다.
(참고: 🟢 화면 정보는 서버 `ui-state`와 브라우저 `localStorage`에 이중으로 있어, 어댑터는 서버 쪽 `ui-state`를 기준으로 읽는다.)

## 10. 개발 순서와 이 설계의 관계

| 순서 | 제품 우선순위 | 이 설계에서 할 일 |
|---|---|---|
| 1 | 인터뷰 기반 크루 생성 | 인터뷰 결과 필드를 `identity.json`과 맞춘다. 패키지 개발 없음 |
| 2 | 크루의 업무 능력 | 해당 없음. 새 필드를 미리 만들지 않는다 |
| 3 | Memory | ⏳ 이때 규격 설계 |
| 4 | 백업·내보내기·가져오기·복원 | 5~9절을 구현. 단계: ⓐ 가져오기 안전 절차를 채팅 zip에 먼저 적용 ⓑ `collectCrew`/`installCrew` ⓒ Share ⓓ Backup |
| 5 | Android→Android 검증 | 시나리오: 폰A Backup → 폰B 복원 → GitHub·권한 다시 설정 → 크루가 예전 지침으로 일하는지 확인 |

## 11. 결정이 필요한 것

1. 3절 2·4번(채팅 zip 가져오기의 미리보기 부재, 권한 규칙의 이름 묶임)은 **패키지와 별개로** 먼저 고칠지.
2. 자료 파일 선택 화면의 자세한 모양(파일별 체크 / 폴더별 체크).
3. 같은 이름 크루가 있을 때의 이름 규칙(번호 붙이기 vs 사용자에게 묻기).
4. ⏳ Memory의 단위(크루별/방별) — 3순위에서 결정.

## 12. 이번 범위에서 하지 않는 것

CLI, Linux·PC 실행, YAML, 다중 두뇌, 마켓·배포, 스킬·워크플로·평가 규격, 서명·암호화, 인증정보 이전, `memory/` 디렉터리.
